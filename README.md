# Harness 网页助手桥接（0.2 测试版）

让 DeepSeek Harness 像派子任务一样，向你已登录的 ChatGPT 网页发问题、取回回答，再在同一聊天里追问。包含 Harness 插件和 Chrome/Edge 浏览器扩展，两部分需同时启用。

**当前状态（2026-10-06）**

- 本地单元测试 **33/33 通过**（`node --test tests/*.test.mjs`，假环境，不碰真实账号）。
- **ChatGPT 已真实联测通过**：新会话首条消息、已有会话追问、整页重载后接管，均跑通并在同对话内完成往返。
- **DeepSeek 与 Gemini 未启用**。两者的选择器仍是未经验证的占位值；DeepSeek 已按用户要求移出使用范围。请勿声称它们可用。
- 已知限制与缺陷见 [自愈系统维修说明_20261006.md](自愈系统维修说明_20261006.md)。

## 安装一次

1. 在 Harness 的 Creator/插件开发会话中，粘贴本目录的 [安装到Harness.txt](安装到Harness.txt)。它会通过原生插件管理器安装本目录，不需要改配置文件。看到安装结果 `application=applied` 后，让它调用 `web_chat_status`。若显示需要重启，保存当前工作后再自行重启。
2. 在 Edge 打开 `edge://extensions`（Chrome 为 `chrome://extensions`），打开“开发人员模式”，点击“加载解压缩的扩展”，选择本目录的 `extension` 文件夹。
3. 打开扩展的“设置”，将 `C:\Users\<你的用户名>\.dsh-web-chat-bridge\pairing.txt` 中的配对码填进去。配对码由 Harness 插件首次成功启动时生成；不要发给网页 AI，也不要贴进聊天。端口默认 `32145`；只有改过 Harness 插件端口时才需要一起改，或点“检查本机桥在线”让它自动找到并记住。
4. 打开并登录目标网页，安装扩展前就打开的页面先刷新。点浏览器工具栏里的扩展，给当前聊天起名（如 `chatgpt`），点击“连接当前聊天”。每个名称只绑定一个聊天；可以用不同名称连接多个聊天。

## 日常怎么用

**推荐：先写文件，再发一句短招呼。**

```
你（在项目目录下写文件）→ _给GPT的简报_20261005.md
你（对 Harness 说）→ 细节我都写在 _给GPT的简报_20261005.md 里了，你看下，重点帮我挑逻辑漏洞
```

理由有两条，都不是风格问题：

- **长消息会触发网页版风控。** 实测触发过
  `Unusual activity has been detected from your device`，
  短招呼 + 文件引用既像人聊天，又保住内容完整。
- **网页 AI 读不到本机路径。** 文件要真被它看到，得由你当附件上传，
  或把内容复制进对话。不要让它写"请阅读 E:\xxx.md"——对方读不到，只会白等。

派单工具会拦截超过 **100 字**的任务文本，并提示改用文件。

## Harness 可调用的工具

| 工具 | 作用 |
|---|---|
| `web_chat_dispatch` | 指定助手名称、招呼语和本次唯一编号，马上返回任务号 |
| `web_chat_status` | 查询连接及任务状态，默认不重复读取回答正文 |
| `web_chat_wait` | 每次最多等 45 秒，再返回状态和回答；等候本身不调用其他模型 |

同一任务重试必须沿用 `request_id`；真正的新追问才换编号。不同网页助手可同时处理任务，同一聊天一次处理一个。只有 `complete` 算完整回答，`uncertain` 表示需要检查，不能当成功。

默认每次给 Harness 最多返回 12000 字符，截断会明确标记；完整已接收文本保存在本机
`C:\Users\<你的用户名>\.dsh-web-chat-bridge\answers\任务号.txt`（工具返回其准确路径）。
状态另存 `tasks.json`。单条回答最多 120000 字符，过长回答不会假报完成。

## 自动化到什么程度（以及边界）

派单前会**按需**把浏览器这一侧补齐，常态几乎不花时间：

1. **快检**（毫秒级）：调试端口、扩展、ChatGPT 标签页是否都在。
2. 快检不过才做**完整维修**（约 15 秒）：拉起专用浏览器 → 挂载扩展 →
   必要时重载页面重新注入内容脚本 → 注册别名。
3. 把 **ChatGPT 的思考强度拉到最高档**（见下）。
4. 派单被拒时**强制维修并原样重试一次**——复用同一个 `request_id`，所以即使
   上一次其实已经成功、只是回执丢了，也不会重复发送。

**思考强度**：网页版默认可能停在低档（实测遇到「中」＝1/4），低档给的是
快速反应式回答。插件会在派单前检测并拖到最高档，同一标签页 10 分钟内不重复查。

**专用浏览器隔离**：自动拉起的是一个**独立 profile** 的浏览器
（默认 `C:\dsh-web-chat-profile`），只加载桥接扩展，不读取你日常浏览器的任何数据。
调试端口只监听 `127.0.0.1`。相关路径可用插件 config 覆盖
（`debugPort`、`chromeProfileDir`、`extensionDir`、`launcher`）。

## 断线、额度耗尽和误操作

- 派出的任务先存盘，再交给浏览器；发送过程不明、刷新中断、Harness 重启时不自动重复发送。
- 遇到“未确认”，先看原聊天。必要时使用扩展里的“我已检查网页，解除挂起任务”，
  或在 Harness 里走本机解除接口（见维修说明），再决定是否重新派单。
  解除挂起并不会停止网站自身的生成，请先在网页确认它已结束。
- **任务台账是全局共享的。** 一个聊天留下的卡单会挡住**所有**会话的派单；
  遇到 409 先怀疑这个，别怀疑参数。
- 已有文字草稿、网页正在生成、找不到正确输入框或无法确认新回答结束时，
  停止本次自动操作，不覆盖草稿、不拿旧回答交差。
- 网页聊天必须保持打开。浏览器让后台标签休眠时收发可能延迟，恢复标签后继续检查。
  网站改版可能需要调整适配，设置页保留少量高级选择器选项。
- 网页调用仍受原套餐限制，Harness 阅读问题和回答仍消耗自己的额度；
  本机轮询和存盘不额外调用模型。

## 网页版风控（务必遵守）

三条纪律：**不复读同一句话**、**间隔要够**（插件已限最小 120 秒）、**不批量抓取**。
触发后页面会回 `Unusual activity has been detected from your device`，
那是设备级限流，通常几天内自行过期。**越戳越可能升级，停下来等。**

## 本地验证与实现范围

```powershell
node --test tests/*.test.mjs
```

测试使用临时目录、随机本机端口和模拟网页回执，**不访问真实账号、不发送项目资料**。
浏览器扩展的页面控件必须另做真实联测。

桥只监听 `127.0.0.1`，浏览器用配对码连接。扩展只请求聊天网站和本机桥的访问权限；
不读取 Cookie、密码或 API 密钥，不调用网站私有接口。原理采用浏览器官方的
[内容脚本](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)、
[消息传递](https://developer.chrome.com/docs/extensions/develop/concepts/messaging)和
[扩展跨域请求](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)。

状态文件可能包含你主动派出的文本和网页回答，请按项目资料保管。
这里没有部署常驻外部服务器，没有修改项目研究代码、行情或原有 Harness 配置。
